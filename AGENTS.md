- Product photos must live in storage as URLs, never base64 in rows (DB trigger rejects `data:`); inline images once overloaded the database.
- Browse loads products in pages of 24 via useInfiniteQuery; never fetch the full catalog in one query.
- Photos are compressed client-side (src/lib/compressImage.ts, 1600px JPEG) before upload to keep storage and page weight small.
- Social videos are branded (signature audio + code badge) in the admin's browser with ffmpeg.wasm (src/lib/brandVideo.ts) and saved to `<uid>/social/<product_id>.mp4` before buffer-publish; edge functions can't run ffmpeg and this keeps processing free.
- buffer-publish must send `metadata.instagram.type = "reel"` (and facebook reel) — Buffer rejects Instagram videos without a post type.
- Chat booking fees: the fee amount is computed by a DB trigger from the accepted offer and only `grant_booking_fee` (via auto-approve or admin review) may set `chat_conversations.is_booking_confirmed`; clients can't self-confirm a booking.
- Chats are opened by conversation id (`/chat?id=`); `/chat?product=` is only for a buyer starting her own chat — sellers have one chat per buyer.
- Other users' profiles are read only via `get_public_profiles` (src/lib/publicProfiles.ts) and paid-booking contacts via `get_booking_contacts`; the profiles table is own-row/staff only so phones, push tokens and codes never leak.
- Sign-up email verification runs in the `email-verification` edge function (unconfirmed account + server token); never store passwords or tokens in client-reachable tables.
- Buyers get a seller's private extra photos only through the `product-private-images` edge function; storage reads in product-private-media are owner/admin only.
- Client uploads to product-images and booking-videos must start with `<uid>/` — storage insert policies require it.
- Public listing text is screened for contact info by src/lib/listingContactFilter.ts and mirrored by the `listing_text_has_contact` DB trigger on products (changed fields only); update both together.

- Listing correction requests are super-admin-only and enforced by a products trigger; unchanged activation (including sold-status RPCs) cannot bypass corrections, and seller saves republish only after actual changes plus own-media confirmation.
- Android pushes use the transparent `ic_stat_notification` B drawable and manifest accent resource; chat and reminder payloads select the same drawable so launcher backgrounds never become white squares.
